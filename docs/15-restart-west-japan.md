# 西日本再開設計（2026-10-13）

## 要望と過去の判断

原始要件と全会話のユーザー依頼・完了報告を再読した。目的は、技士会公式サイトの学習機会を横断して探すサービスで、Web・オンデマンドを重視する。企業共催も掲載対象。追加サーバー・DB・SaaS費用を避ける。日常運用は日本語の専用管理画面から行い、スプレッドシートを直接編集する必要をなくす。

西日本の今回の範囲は、九州・沖縄8県、中国・四国9県、近畿6府県、東海4県、北陸3県の30府県と日本臨床工学技士会。甲信越は次段階とする。全県を登録するだけでは完成とせず、実取得結果を県別に記録する。

## 実証した問題

- GitHubのmainは中四国・近畿追加前で、手元の未反映コードが残っていた。
- 公開JSONは2026-09-04T23:04:13Zの4件。管理シートには期限が過ぎた公開行が残っていた。
- Sourcesの有効・無効が日次収集に反映されず、Repository Variableのみが使われる。
- 候補はEventSourcesに毎日追記され、新規EventsとReviewQueueへの接続がない。
- 料金・定員に隣接項目が混入する。最初の日付を開催日とみなすため記事投稿日との混同がある。
- 既存Eventsを直接自動更新しており、管理者修正・確認済み料金を保護できない。
- AI抽出・PDF処理の部品はあるが、収集から管理判断まで接続されていない。
- 管理画面のGitHub接続はトークンの存在だけで判定している。以前のトークンの期限は2026-08-06で、現在の有効性は未確認。

## 採用方針

GitHub Pages、GitHub Actions、非公開Sheets、GASを維持する。県ごとの発見方法と許可URLを明示し、共通の文字抽出・根拠検証・重複処理を共有する。動的サイトは公開ページを描画する補助取得を使い、会員限定情報・認証APIは取得しない。

新候補は安定したIDで確認待ちEventsとReviewQueueに保存する。同じ候補の再取得は既存行を更新し、追記を増殖させない。自動抽出値はAutoFieldValuesへ保存し、管理者修正値はFieldOverridesへ保存する。公開・非公開など管理者の判断を自動処理で変更しない。

県別に取得成功・失敗・技術保留・候補0件を区別する。Sourcesの停止設定を日次収集にも反映する。日次処理は地域ごとに分割し、取得キャッシュを継続保存する。公開処理は全地域の完了後に一度行う。

AIはHTML/PDFの構造理解を補助し、返された根拠を入力本文と照合する。日時・参加費・単位に根拠がなければ採用しない。URLは取得文書内のものだけを認める。AIの確信度だけで料金を確認済みにしない。API接続は専用キーの保存が完了してから行う。
